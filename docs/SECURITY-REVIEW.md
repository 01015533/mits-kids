# Security review and implementation record — 0.4.2+6

Reviewed against Android's [security best practices](https://developer.android.com/privacy-and-security/security-best-practices) and [security checklist](https://developer.android.com/privacy-and-security/security-tips). This is an implementation review, not a security certification or a guarantee against every attack.

| Finding | Implemented control | Verification and scope |
| --- | --- | --- |
| Weak PIN verifier | 32-byte random salt, PBKDF2-HMAC-SHA256 at 600,000 iterations, then HMAC with an Android Keystore key; constant-time comparison; no PIN logs | Kotlin compiles against Android 36 and Flutter embedding. Independent JVM fixture checks compare derivation against Python's standard implementation. Native Android Keystore authentication passed on the emulator. Hardware-backed protection still depends on the target device. |
| Repeated guesses | Attempts commit before verification, increasing delays up to five minutes, persisted across restarts; monotonic time during the same boot; conservative delay after reboot | Backoff checks run on JVM. The isolated Android harness now verifies migration, five-failure cooldown across process restart/reboot, and post-reboot Keystore authentication; see the measured validation record. |
| First-PIN claim | Dedicated setup gate across the whole app; PIN confirmation; existing-PIN verification before migration | Initial adult identity relies on the parent controlling installation. Clearing application data remains outside the app's control. |
| PIN change | An active parent session, current-PIN verification with persisted throttle, confirmed new PIN, existing Keystore key and guarded credential commit | No reset bypass. A lifecycle interruption cannot restore a locked session; a completed commit immediately before interruption may leave the new PIN active. |
| Unlocked background/session | In-memory Parent authority, five-minute expiry, immediate lock on inactive/background; late responses discarded; parent dialogs closed; WebView removed; unapproved saves cancelled | An explicitly approved save has separate authority for that exact video only, an overall 30-minute limit and safe cancellation. Parent/Browse remain locked and current rules are checked before publication. Backups still cancel on lock. Consult measured validation for lifecycle and background-job coverage. |
| WebView bridge and local file exposure | Internal JavaScript bridge disabled at creation; file/content and cross-file access disabled; HTTPS host navigation allowlist; mixed content blocked; Safe Browsing enabled; permissions, popups and file chooser denied | Settings checked against the installed plugin implementation; runtime website compatibility remains an emulator check. |
| DOM filtering bypass | Live browsing parent-only; native child player opens approved local records only; current rules checked again before playback | Playback-policy tests reject missing approval/identity and demonstrate title/channel/channel-ID revocation. No claim that the DOM filter alone enforces access. |
| Accidental playback input | In-app touch/focus/semantics suppression with a two-second hold to unlock; volume-key consumption scoped to the locked, resumed, focused activity | This is a convenience, not authentication. Power/Home/system shortcuts remain available. No new permissions or device-management components. Physical volume behavior requires the Lenovo test. |
| Media transport | Separate Dart HTTPS/host policy with manual validation of every redirect; strips credentials across origins; no certificate overrides | Tests cover cleartext, private literal addresses, lookalikes, credentials, ports, redirect loops and cross-origin headers. HTTPS CDNs can resolve to changing public addresses; this is not a network firewall. |
| Storage and untrusted paths | Private app storage; canonical-path containment for playback/deletion; native mux restricted to offline staging; byte bounds; eight saved entries; reserve-space checks; file-hash check before playback; recognized unreferenced artifact cleanup | Missing/damaged records are retained for deliberate parent deletion and occupy slots. Cleanup preserves referenced and unknown files and does not follow symlinks. Hashes detect changes relative to saved metadata, not a compromised OS capable of rewriting both. See the validation record for measured tests. |
| Backups | `allowBackup=false`, explicit cloud/device-transfer exclusions and legacy backup exclusions | Updater writes resources. APK checker verifies compiled policy and manifest references. No retroactive deletion of pre-existing backups. |
| Explicit encrypted export/restore | A separate confirmed backup password; parent reauthentication after Android's document picker; bounded authenticated archives; fresh video approval; current rules kept unless separately confirmed | No PIN/verifier, Keystore material or signing key in the archive. Existing files are not replaced and no loose MP4 import is provided. See `ENCRYPTED-BACKUP.md`, the design record and measured validation results before relying on backups. |
| Permissions and APK exposure | Main manifest requests Internet; Media3 adds network-state and wake-lock permissions; exact final allowlist and component checks enforce the [APK policy](APK-POLICY.md); dependency-added profiling receiver removed from release | Normal launch activity remains exported. Device-admin bindings/metadata, HOME launcher category and enabled lock-task declarations are rejected. The scoped AndroidX signature permission remains allowed. |
| Release integrity | Minimum API 26; explicit TLS/system trust policy; release debugging/testOnly disabled; persistent user-owned signing key required; debug-certificate rejection in APK checker | Final release checker verifies certificate signature and prints fingerprint. User must compare against their own key. No Play Integrity server introduced for this offline sideloaded app. |
| Dependencies | WebView 6.2.0-beta.3 evaluated and retained for AGP 9 compatibility; per-lockfile advisory checker included | Consult `dependency-audit.json` and `VALIDATION.md` for the actual queried package set and freshness. Earlier audit counts do not certify the current lockfile. No claim of a complete Android/OS vulnerability scan. |

The app uses Flutter engine channels for its own native operations and opens no local listening socket or discovery service. It does not dynamically download native executables or enable the extractor's external JavaScript solver. YouTube itself remains a third-party website with its own network requests during parent browsing.

The main remaining system boundary is Android itself: a child able to launch
another browser, clear app data or uninstall the app can bypass an
application-only gate. Kiosk mode, device-owner/admin enforcement and device
management are permanently excluded by the maintainer; they are not a future
mitigation in this project. Keep Android and System WebView patched.

See `VALIDATION.md` for measured results and `SECURITY-UPDATE.md` for emulator checks and release instructions.
